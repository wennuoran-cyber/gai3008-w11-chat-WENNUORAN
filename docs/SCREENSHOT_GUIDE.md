# README 스크린샷·GIF 촬영 지침

과제 조건: **README에 개선된 화면 스크린샷 또는 움직이는 화면(GIF)을 넣는다.**
이 문서는 무엇을 찍고, 어떻게 그 화면을 만들고, README 어디에 어떻게 넣는지 정리한다.

---

## 1. 결과물 한눈에 보기

| 파일 | 종류 | 보여 줄 것 | 관련 할 일 |
|---|---|---|---|
| `docs/screenshots/01-chat.png` | 스크린샷 | 이전 대화가 있는 기본 화면 (말풍선 좌우, 입력창 힌트) | 실습 1 — 2·3·4 |
| `docs/screenshots/02-suggestions.png` | 스크린샷 | 입력 예시 패널을 펼친 화면 | 실습 1 — 4 |
| `docs/screenshots/03-error.png` | 스크린샷 | 500 오류 말풍선 + 다시 시도 버튼 | 실습 ④ — 1·2 |
| `docs/screenshots/04-retry.gif` | GIF | 오류 → 다시 시도 → 응답 도착 | 실습 ④ — 2·3·4, 완료 기준 |
| `docs/screenshots/05-backoff.gif` | GIF | 429 → 1초 대기 안내 → 자동 재시도 → 응답 | 실습 ④ — 5 |

**최소 요건**은 스크린샷 1장 또는 GIF 1개다. 위 5개를 다 넣으면 실습 1과 실습 ④의 할 일을 모두 화면으로 보여 줄 수 있다.
시간이 부족하면 `01-chat.png`, `03-error.png`, `04-retry.gif` 3개만 넣는다.

## 2. 촬영 준비

```bash
flutter pub get
flutter run -d chrome
```

- **휴대폰 크기로 보기**: Chrome 개발자 도구(⌥⌘I) → 기기 툴바(⇧⌘M) → **iPhone 12 Pro (390×844)** 선택. 배율은 100%.
- **라이트 모드**로 찍는다(시스템 다크 모드면 앱도 어둡게 나온다). 다크 모드 한 장을 추가로 넣어도 좋다.
- 앱을 새로 띄운 상태(가짜 대화 4줄만 있는 상태)에서 시작한다. 중간에 꼬이면 터미널에서 `R`(핫 리스타트).
- 앱바 오른쪽 🧪 **오류 재현** 메뉴로 다음 요청의 결과를 고른다. 정상이 아닌 모드를 고르면 앱바에 모드 이름이 빨간 글씨로 보인다.

### 타이밍 (짧게 지나가는 화면을 찍을 때 참고)

| 화면 | 보이는 시간 |
|---|---|
| AI 타이핑 점 | 전송 후 1.2초 |
| 429 "1초 뒤 다시 보내요 (1/2)" | 1초 (이어서 "2초 뒤 … (2/2)"는 2초) |
| timeout 대기 | 전송 후 5초 동안 타이핑 점 |
| 오류 말풍선 | 다음 전송이나 다시 시도 전까지 계속 |

짧게 지나가는 화면은 스크린샷보다 **GIF로 찍는 편이 쉽다**.

## 3. 화면별 만드는 방법

### 01-chat.png — 기본 화면
1. 앱을 새로 띄운다(메뉴는 "정상 응답").
2. 그대로 찍는다. 가짜 대화 4줄(오른쪽 사용자 / 왼쪽 AI)과 입력창 힌트 "무엇이든 물어보세요"가 보이면 된다.

### 02-suggestions.png — 입력 예시 펼침
1. 대화 영역 맨 위 **💡 입력 예시** 줄을 누른다.
2. 예시 4개가 왼쪽에 세로로 펼쳐진 상태에서 찍는다.

### 03-error.png — 오류 말풍선
1. 🧪 메뉴 → **500 서버 오류**.
2. 아무 문장(예: "오늘 날씨 알려줘")을 보낸다.
3. 1.2초 뒤 왼쪽에 붉은 **서버 오류 (500)** 말풍선과 **다시 시도** 버튼이 뜨면 찍는다.
   - 앱바에 "500 서버 오류"가 함께 보이게 찍으면 어떤 상황인지 설명이 된다.

### 04-retry.gif — 오류 → 다시 시도 → 응답 (약 5~8초)
1. 🧪 메뉴 → **500 서버 오류**, 녹화 시작.
2. 문장을 보낸다 → 타이핑 점 → 오류 말풍선(1.2초 뒤).
3. 🧪 메뉴 → **정상 응답**으로 바꾼다.
4. 오류 말풍선의 **다시 시도**를 누른다 → 오류가 타이핑 점으로 부드럽게 바뀌고(AnimatedSwitcher) → 1.2초 뒤 응답 "아직 미구현되었습니다."
5. 이어서 새 문장을 하나 더 입력해 보내면 "오류 뒤에도 입력이 된다"까지 보여 줄 수 있다. 녹화 종료.

보여 줘야 할 포인트: 오류가 화면에 **남는다**, 다시 시도 때 **사용자 말풍선이 늘지 않는다**, 오류 뒤에도 **입력이 된다**.

### 05-backoff.gif — 429 지수 백오프 (약 5초)
1. 🧪 메뉴 → **429 한 번 후 성공**, 녹화 시작.
2. 문장을 보낸다 → 타이핑 점 → "요청이 많아 1초 뒤 다시 보내요 (1/2)" → 타이핑 점 → 응답. 녹화 종료.
3. (선택) 메뉴를 **429 요청 과다**로 바꿔 한 번 더 찍으면 1초 → 2초 대기 후 **요청이 너무 많아요 (429)** 오류까지 나온다(약 8초).

## 4. GIF 만들기

- **macOS 기본**: ⇧⌘5 → "선택 부분 기록"으로 휴대폰 화면 영역만 녹화 → `.mov` 저장.
- `.mov` → GIF 변환 (ffmpeg가 있을 때):
  ```bash
  ffmpeg -i retry.mov -vf "fps=12,scale=390:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" docs/screenshots/04-retry.gif
  ```
- 용량은 GIF 하나당 **5MB 이하**를 목표로 한다(GitHub에서 빨리 뜬다). 크면 `fps=10`, 길이를 줄인다.
- 스크린샷은 PNG, 폭 390~780px이면 충분하다.

## 5. README에 넣기

README의 `## 화면` 섹션에 있는 주석 한 줄

```markdown
<!-- 스크린샷·GIF 자리. 넣을 내용은 docs/SCREENSHOT_GUIDE.md 참고 -->
```

을 아래 내용으로 바꾼다(찍지 않은 파일의 칸은 지운다).

```markdown
| 기본 화면 | 입력 예시 | 오류 말풍선 |
|---|---|---|
| <img src="docs/screenshots/01-chat.png" width="240" alt="이전 대화가 보이는 기본 채팅 화면"> | <img src="docs/screenshots/02-suggestions.png" width="240" alt="입력 예시 패널을 펼친 화면"> | <img src="docs/screenshots/03-error.png" width="240" alt="500 서버 오류 말풍선과 다시 시도 버튼"> |

| 오류 → 다시 시도 | 429 지수 백오프 |
|---|---|
| <img src="docs/screenshots/04-retry.gif" width="240" alt="오류 말풍선에서 다시 시도를 눌러 응답을 받는 과정"> | <img src="docs/screenshots/05-backoff.gif" width="240" alt="429 뒤 1초 기다렸다가 자동으로 다시 보내 응답을 받는 과정"> |
```

- 경로는 **상대 경로**(`docs/screenshots/...`)로 쓴다. 그래야 내 저장소(fork)의 GitHub 화면에서 바로 보인다.
- `alt`에는 무엇을 보여 주는 화면인지 한 문장으로 쓴다.
